# مساحة الكاتب | سجل التنفيذ والتحقق — الإصدار v3
**تاريخ الإعداد:** 4 نوفمبر 2026
**الحالة:** نسخة تطويرية لا تُعتمد إنتاجيًا قبل نجاح اختبارات GitHub والنشر والتشغيل
**المرجع الأعلى:** [التوجه الاستراتيجي المعتمد](التوجه_الاستراتيجي_المعتمد_مساحة_الكاتب_2026-11-03.md)

## 1) ثوابت المشروع
- اللغة العربية هي لغة الواجهة والتحليل والمساعدة.
- المؤلف لا تُكتب الفصول أو المشاهد أو الحوارات نيابة عنه.
- الأولوية النوعية للرواية والقصة القصيرة، مع استمرار اختبار بقية الأنواع الموجودة في النسخة.
- لا يشارك النص مع نموذج خارجي دون طلب وموافقة، ولا يُشارك مع دار نشر دون موافقة محددة.
- لا يُعتبر تشابه موضوعي اتهامًا بالانتحال ولا يُدعى فحص نص كتاب لم يُتح وصوله قانونيًا.
- آخر ثلاث مراجعات تحريرية اعتيادية؛ يجب التخطيط لاحقًا للنسخ المرجعية المحفوظة بإرادة المؤلف.

## 2) المنفذ برمجيًا في فرع التطوير
- [x] وحدة `literary_core`: سياق عابر للفصول قائم على كلمات مفتاحية وشواهد حقيقية مع معرف الفصل ورقم الإصدار وبصمة النص؛ **استرجاع جزئي وليس فحصًا شاملًا أو RAG دلاليًا كاملًا**.
- [x] حفظ ملاحظات أدبية من النموذج مع شاهد مطابق من مقطع مصدر واحد، وحالة مستقلة للمؤلف: جديد/نوقش/مقبول/مرفوض/عولج.
- [x] سجل وقائع وملخصات وقرارات معتمدة يمكن عرضه كذاكرة سردية أولية.
- [x] تضمين الملاحظات الأدبية في النسخ الاحتياطية بصيغة `writer-cloud-v2` وتوافق الاستيراد القديم.
- [x] مرصد فهرسي اختياري عبر Open Library مع إذن صريح لكل بحث وروابط حقيقية؛ **لا مقارنة نصية كاملة ولا ضمان شمول الأعمال**.
- [x] استيراد DOCX وإضافة فصول دون حذف الموجود وتصدير مخطوط DOCX باتجاه عربي؛ يحتاج تدقيق إخراج أوسع.
- [x] طبقة مزودين متاحة للاختبار: OpenAI المباشر، أو Groq بقائمة نماذج محددة، أو OpenRouter بنموذج يحمل لاحقة `:free`؛ **لا انتقال تلقائي ولا استدعاء مدفوع احتياطي**.
- [x] واجهات الكاتب للنقد، والمصادر، وذاكرة العمل، وWord.
- [x] اختبارات API تستهدف الشواهد المختلقة، وعزل الكتاب، وحفظ الملاحظات، والاستيراد والتصدير، وموافقات البحث، والفشل عند انتهاء الحصة.

## 3) ما لا يجوز ادعاء اكتماله
- [ ] اتصال حي بنموذج AI ونتائج نقد أدبي عربي محكّمة؛ عدم وجود مفتاح يعني إرجاع حالة عدم التفعيل بوضوح.
- [ ] تدريب أو Fine-tuning على مكتبة كتب مرخصة.
- [ ] RAG دلالي/زمني متقدم يغطي مخطوطًا طويلًا كاملًا دون اقتطاع.
- [ ] شبكة أحداث زمنية تُستخرج وتُعتمد تلقائيًا بدقة احترافية.
- [ ] محرر نص غني يوازي Scrivener وReedsy في جميع وظائفه.
- [ ] إدارة أثر التعديل آليًا وقياس نمو المهارات على مدة طويلة.
- [ ] مقارنة التشابه النصي مع مكتبة كتب محمية أو مستودع مفهرس شامل.
- [ ] تكامل دور النشر والعقود وإدارة حقوق الاستغلال؛ تبقى ضمن المسار المعتمد اللاحق.
- [ ] استعادة نسخة من بيانات إنتاج Render الحية؛ لا يجوز تغيير القاعدة أو حذفها اعتمادًا على اختبارات SQLite فقط.
- [ ] إثبات استخدام النصوص الحقيقية وخصوصيتها لدى مزود خارجي.

## 4) البنية
- PostgreSQL يحمل المشروع والفصول والوقائع وسجل المراجعات وتاريخ التحليل.
- منسق واحد في Python يختار المهارة والمزود صراحة. النماذج لا تتخذ صلاحيات وصول مباشرة إلى المخطوطات.
- نص المستخدم ومحتوى الكتب الخارجية بيانات غير موثوقة، ولا يُسمح لهما بالتحكم في تعليمات المساعد أو مسار العمليات.
- عدم احتجاز المؤلف: نسخ JSON كامل وWord للتحرير البشري.
- عملية تحرير النص هي المرجع؛ التحليل لا يكتب فوقه تلقائيًا.

## 5) بوابات الاعتماد
1. اختبارات Python وPostgreSQL وJavaScript وChromium ناجحة على فرع الإصدار.
2. اختبار فتح الواجهة و/health ومسارات 401 للزوار على Render بعد النشر.
3. توثيق إصدار Git الفعلي في الخدمة الحية.
4. اختبار حالة `ai_configured`: لا يقال «النقد يعمل» إذا كانت `false`.
5. اختبار استعادة منفصل قبل السماح بمخطوطات حقيقية.
6. تحكيم أدبي على نصوص سليمة وأخرى تتضمن أخطاء؛ يجب عدم مساواة نجاح اختبار API بنجاح النقد.

## 6) العمل التالي حتى نهاية نوفمبر
تفعيل مزود نموذج واحد بعد حسم ضوابط البيانات؛ اختيار النموذج بناءً على مجموعة نقد عربية محكّمة؛ تطوير الاسترجاع الزمني والعلائقي؛ تقديم التلميحات والمراجعة والتدريب أثناء الكتابة؛ تحسين المحرر وDOCX وEPUB/PDF؛ بناء مكتبة معرفية بحقوق واضحة؛ ثم اختبار أثر المساعد لدى كتاب حقيقيين بموافقتهم.
