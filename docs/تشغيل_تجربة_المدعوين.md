# تشغيل تجربة المدعوين — مساحة الكاتب

## حالة النشر
- الواجهة: https://writer-space-pilot-room.onrender.com
- إدارة الدعوات: https://writer-space-pilot-room.onrender.com/admin
- مستودع المصدر: https://github.com/mutebmhs-cloud/room
- العمل الحالي مخصص **لبيانات مصطنعة فقط**.
- إعداد الدعوات PILOT_INVITE_MODE=1. الدخول باسم مستخدم ورمز شخصي دائم حتى يلغي المدير الرمز أو يدوّره.
- النظام يُظهر دليل الاستخدام بعد أول دخول للكاتب، ويمكن إعادة فتحه من القائمة.
- يطّلع المدير على أعمال من وافقوا على المراجعة، في وضع القراءة فقط، ويُسجل كل اطلاع ويُعرض للكاتب.
- يوجد نموذج بلاغات وصعوبات الاستخدام لدى الكاتب، ويظهر في لوحة الإدارة.
- المساعد الذكي جاهز من الناحية البرمجية لاستقبال OPENAI_API_KEY لاحقًا، ولا يُرسل نصًا قبل اختيار الكاتب؛ **لم يُختبر اتصاله الفعلي بعد**.

## ضروري: تفعيل PostgreSQL على Render
خدمة الويب الحالية تستخدم SQLite على القرص المؤقت Render Free، وبالتالي قد تُفقد كل الدعوات والأعمال والبلاغات عند كل إعادة نشر أو إعادة تشغيل. قاعدة PostgreSQL المجانية أنشئت باسم writer-space-pilot-db، ولكن **ما زال الربط الفعلي غائبًا**.

تم إعداد ملف render.yaml لربط القاعدة الموجودة آليًا باستخدام fromDatabase دون إدخال كلمة المرور في المستودع.

خطوة واحدة تحتاج إلى مالك حساب Render:
1. من https://dashboard.render.com اختر **+ New > Blueprint** ثم اربط المستودع mutebmhs-cloud/room والفرع main والملف render.yaml.
2. راجع المعاينة قبل التأكيد: يجب أن تظهر **الخدمة القائمة writer-space-pilot-room والقاعدة القائمة writer-space-pilot-db**. إذا ظهر إنشاء موارد جديدة أو خطة مدفوعة، **لا توافق**.
3. وافق على تطبيق Blueprint الذي يضبط DATABASE_URL من القاعدة، وAPP_SECRET بصورة عشوائية، وPILOT_EPHEMERAL=0.
4. لا تكتب أي كلمة مرور أو رابط قاعدة بيانات في GitHub أو المحادثة.
5. افتح /health بعد النشر. لا تعتمد البيانات قبل أن يعرض durable_storage:true وephemeral:false.
6. نفذ اختبارًا مصطنعًا: أنشئ دعوة وعملًا، ثم أعد نشر الخدمة، وتأكد من بقاء الدخول والعمل وسجل المراجعة بعد النشر.

قاعدة PostgreSQL المجانية الحالية تنتهي بتاريخ **2026-11-30**، ولا تتضمن نسخًا احتياطية مُدارة. لذلك حل الربط مؤقت لمدة 30 يومًا وليس تخزينًا دائمًا ممتدًا. يلزم نقل الخدمة إلى تخزين مستمر بعد اختبار استعادة النسخ قبل دعوة مؤلفين بمخطوطات حقيقية.

## كيف يدخل المدير؟
- اسم المستخدم الافتراضي: pilot-admin (إلا إذا ضُبط PILOT_ADMIN_USERNAME).
- رمز المدير العشوائي الأول يُولد عند أول تشغيل ويحفظ بصمته فقط في قاعدة البيانات، ويعرض لمرة واحدة ضمن **سجلات Render الخاصة** كسطر يبدأ بـ PILOT_ADMIN_FIRST_RUN_ACCESS=.
- استعمل رمز المدير من سجلات حسابك الخاص ولا تنسخه إلى وثيقة عامة.
- رابط الإدارة: /admin.
- الإدارة تصدر اسم الكاتب (حروف لاتينية صغيرة)، والاسم المعروض، والرمز الخاص. عند تدوير الرمز تُلغى كل الجلسات السابقة.

## منهج التجربة
- لكل كاتب اسم مستخدم ودعوة خاصة لا تتشارك بين كتّاب.
- يصنع الكاتب مشروعًا من الأنواع: رواية، قصة قصيرة، قصة خاطفة، قصة أطفال، سيناريو.
- يدوّن أفكارًا حرة ومخطوطات مصطنعة، ويستخدم البناء والمراجعات ونقطة التوقف، ثم يرسل بلاغًا.
- المدير يراجع المحتوى بعد الموافقة، ويقارن البلاغ بالمحتوى والسلوك، ثم يسجل العيوب حسب الأولوية.
- لا يوجد توليد نص نيابة عن الكاتب. مفتاح AI غير مفعّل حتى تتم إضافته في متغيرات Render بطريقة آمنة.

## التحقق والتغطية
- تشغيل اختبارات API القديمة ودورة الدعوة والموافقة والدخول والتدوير والبلاغات تلقائيًا عبر GitHub Actions.
- اختبار خارجي آلي لمسارات الواجهة وAPI والاعتمادية، دون دخول إلى بيانات خاصة.
- **قيود متبقية:** لا يوجد اختبار محادثة AI حقيقية، ولم يتم إثبات حفظ PostgreSQL على Render، ولا يجوز ضمان بقاء المدعوين في وضع SQLite المؤقت.
