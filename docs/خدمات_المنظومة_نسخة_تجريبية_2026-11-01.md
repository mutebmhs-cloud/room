# مساحة الكاتب — تطوير خدمات النشر والإنتاج (نسخة اختبار 2026-11-01)

## ما أضيف فعليًا
- تبويب «الخدمات والشركاء» داخل كل مشروع كتابة، مع 8 خدمات مرتبطة بنوع العمل.
- ثلاثة مسارات للطلب: متخصص بشري، ذكاء اصطناعي، مزيج منهما.
- وصف متطلبات الخدمة واختيار أقسام المخطوط المرفقة صراحةً. تحفظ نسخة محددة في قاعدة البيانات، ولا تتغير تلقائيًا مع تحرير المخطوط.
- دليل ملفات مهنية ذاتية التصريح، دون اعتماد أو تحقق تجاري، ودعوات محددة من صاحب المشروع. لا يستطيع المدعو قراءة المقاطع إلا بعد قبول الدعوة، ولا يستطيع حساب ثالث قراءة الطلب.
- تبادل الملاحظات ضمن الطلب، إلغاؤه، وإغلاق صلاحية مقدم الخدمة بعد الإلغاء.
- تشغيل مراجعات ذكاء اصطناعي نصية لخدمات التدقيق والتحرير وتحليل السيناريو فقط، مع موافقة جديدة عند كل تشغيل. لا يعيد كتابة أو يحفظ أي تعديلات في المخطوط. يستخدم مفتاح OPENAI_API_KEY الموجود على الخادم، وstore:false.
- يرفض التشغيل الذكي إذا كانت البيئة مؤقتة أو المفتاح غير مضبوط.
- اختبارات صلاحيات العزل والموافقة والدعوات والتدقيق، ضمن مجموعة GitHub Actions.

## ما لا تدعيه هذه النسخة
لا يوجد توليد رسوم آلي فعلي، ولا ربط مكتمل بمقدمي نشر أو إنتاج موثقين، ولا تعاقد أو دفع، ولا موافقات رسمية للنشر أو التوزيع أو الإنتاج. خدمة الرسم والحرفيين هي طلب وتتبع فقط حتى تفعيل مزود وتقييم جودة النتائج.

## اختبارات ما قبل التشغيل العام
1. تأكد من استخدام PostgreSQL دائم، واختبار عملية الاستعادة من نسخة احتياطية.
2. نفّذ ترحيلات قواعد بيانات بإصدارات قبل تغييرات schema اللاحقة؛ create_all ينشئ الجداول فقط ولا يرحّل الأعمدة الموجودة.
3. اختبر العزل في حسابات ناشر ورسام وكاتب فعلية، ثم راجع الصلاحيات والروابط والسجلات.
4. افحص تكلفة المزود الذكي وعقود معالجة النصوص وسجل الموافقات.
5. أضف آليات اعتماد مقدمي الخدمات والإبلاغ عن إساءة الاستخدام.
6. لا تشغل خدمات الدفع أو عقود النشر دون مراجعة نظامية واختبارات تسويات.

## قرار غير محسوم
لا تزال إعادة كتابة الفقرات الأدبية نيابة عن الكاتب خارج النطاق؛ التدقيق يقترح تعديلات موضعية دون تطبيقها.
