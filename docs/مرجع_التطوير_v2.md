# مساحة الكاتب — مرجع التطوير التشغيلي (الإصدار المقترح v2)

**حالة الإصدار:** تطوير واختبار على فرع مستقل، غير منشور لكتّاب الإنتاج. `main` هو الإصدار المنشور الحالي.

## وظيفة المنتج
الكاتب يؤلف النص ويحتفظ بقراره. المنصة تحفظ العمل، وتتعرف إلى موضع الكتابة، وتساعده على تنظيم فهمه ومراجعته. عند تفعيل الاتصال بمزود التحليل، يمكن استخراج المعلومات من الأفكار الحرة وتلخيص الفصول وتقديم مراجعات نقدية مسندة بنص، **بعد اختيار الكاتب وموافقته الصريحة لكل تحليل**. لا تُنشئ فصولًا أو حوارات نيابة عنه.

## المسار الأساسي
1. **الدعوة:** المدير يصدر رمزًا من 10 أحرف وأرقام للكاتب. مراجعة الإدارة محكومة بالموافقة وسجل الاطلاع.
2. **المشروع:** إنشاء عنوان ونوع عمل، ومنع طلبات الإنشاء المكررة ذات العنوان والنوع داخل حساب الكاتب، مع إعادة فتح الموجود دون حذفه.
3. **الأفكار الحرة:** كتابة حرة مع أسئلة اختيارية للرؤية والسؤال المركزي والأثر والهدف الإبداعي. التحليل متاح بطلب مباشر، أو تلقائيًا بعد الحفظ عندما يفعّل الكاتب خيار موافقة واضحًا داخل جلسة المشروع. لا يُرسل النص دون هذا التفعيل.
4. **بناء العمل:** تُعرض الحقول المقترحة مع الشاهد والتمييز بين معلومة صريحة واستنتاج؛ يختار الكاتب اعتماد كل حقل أو تركه.
5. **المخطوط:** كتابة الفصول أو عناصر السيناريو، والحفظ الآمن برقم مراجعة، والتصدير والاستيراد.
6. **ملخص كل فصل:** ملخص يدوي متاح دائمًا، وملخص ذكي مقترح عند الاتصال؛ يظهر تحذير إذا تغيّر نص الفصل بعد اعتماد ملخصه.
7. **الاستمرار:** حفظ آخر تبويب كتابة وفصل وموضع مؤشر؛ استعادة الموضع عند العودة. تبقى ملاحظات الكاتب الاختيارية منفصلة عن آخر نشاط فعلي.
8. **المدرب:** أسئلة غير ذكية متاحة دون API؛ ومع الاتصال يقدم ملاحظات مرتبطة بشواهد من الفصل المحدد دون الكتابة نيابة عنه.

## مصدر الحقيقة
- `Project.scratchpad`: النص الحر الأصلي.
- `Project.structure`: حقول اعتمدها الكاتب، أو ملأها يدويًا.
- `Section`: المخطوط الذي يملكه الكاتب؛ ليس ملخصًا أو اقتراحًا.
- `WriterAnalysis`: مسودات التحليل التي قد تُعتمد أو تُرفض. لا تندمج آليًا.
- `SectionSynopsis`: ملخص مستقل مرتبط ببصمة مصدر، مع حالة `stale` حين يتغير النص.
- `WriterProgress`: آخر موضع كتابة محفوظ، وليس استنتاجًا عن نية الكاتب.

## البيانات والتوافق
الجداول الجديدة تُنشأ إضافة إلى القديمة، دون حذف المستخدمين أو مخطوطاتهم. تصدير المشروع `writer-cloud-v2` يتضمن الملخصات والموضع مع دعم استيراد النسخ القديمة. يحتفظ الخادم بثلاث مراجعات **سابقة** لكل فصل بعد آخر تحديث؛ لا تُحذف المراجعات التاريخية من مخطوط موجود قبل عملية حفظ جديدة. قبل اعتماد أي ترقية للإنتاج يجب إثبات النسخ الاحتياطي والاستعادة وتوافق مخطط PostgreSQL.

## حدود الذكاء الاصطناعي
- `OPENAI_API_KEY` غير موجود في المستودع؛ عند غيابه لا يُدَّعى نجاح التحليل.
- لا يُرسَل النص للتحليل إلا بطلب واضح وموافقة صريحة، أو عند تفعيل خيار التحليل التلقائي داخل جلسة المشروع؛ يُلغى الخيار عند تغيير المشروع أو إعادة فتحه.
- `source_hash` يمنع اعتماد اقتراحات قديمة بعد تغيير النص.
- المعلومات المستخرجة والانتقادات تتطلب شواهد نصية؛ الوجود الحرفي للشاهد لا يضمن صحة تفسيره.
- لا تستخدم بيانات كتّاب حقيقيين قبل مراجعة الخصوصية والأمان وعقد المعالجة ونقل البيانات.

## واجهات API المضافة
- `GET /api/projects/catalog` — قائمة مشاريع خفيفة.
- `GET /api/projects/{pid}/intelligence` — الملخصات والموضع ومسودات الكاتب.
- `POST /api/projects/{pid}/intelligence/analyze` — تحليل بموافقة صريحة.
- `POST /api/projects/{pid}/intelligence/analyses/{aid}/apply` — اعتماد نتائج محددة.
- `POST /api/projects/{pid}/intelligence/analyses/{aid}/dismiss` — رفض.
- `PUT /api/projects/{pid}/intelligence/sections/{sid}/summary` — ملخص يدوي.
- `PUT /api/projects/{pid}/intelligence/progress` — موضع التوقف.
